# 《山》项目省额度准则 v1.0

目标：在不牺牲成品质量、可维护性和可验证性的前提下，尽可能减少 ChatGPT / Codex(Astra) 的上下文读取、推理、生成和返工成本。

| 环节 | 省额度做法 | 避免事项 | 默认执行方式 |
|---|---|---|---|
| 任务拆分 | 一次只做一个积木；每个 TASK 明确 READ ONLY / CREATE / UPDATE / FORBIDDEN | “把整本刊都看一遍再做” | 小任务、短上下文、单一目标 |
| 仓库读取 | 只读当前 TASK 点名文件；冻结模块不重复读源码 | 扫描全仓库、全稿件、全部历史 commit | AGENTS.md + 当前 TASK 导航 |
| 规格管理 | 数值集中在 tokens/spec；视觉参考只说明气质 | 同一参数在多个文件重复写 | 单一真源 Source of Truth |
| 代码生成 | 新增独立模块，不重写旧模块；优先复用现有函数 | 单体巨型脚本、重复生成整文件 | 最小 diff / 小函数 / manifest-driven |
| Bug 修复 | 只给报错、文件、行号、现象；要求最小修复 | “全面检查并优化所有代码” | Bugfix-only prompt |
| 冻结机制 | 通过实机验证后 FROZEN + tag | 后续为了“顺便统一”再改冻结代码 | visual overlay / new layer |
| 测试 | Node 做结构测试；InDesign 只做宿主/API/视觉关键验证 | 每次全量人工回归 | 分层测试，必要测试优先 |
| 实机验证 | 一次截图只验证关键问题；优先看弹窗、页数、overset、Parent | 大量无关截图、反复完整导出 | 最小验收清单 |
| 视觉设计 | ChatGPT先定方案、参数和参考局部；Codex只实现 | 让 Codex 自己“设计” | 我先设计，Astra照规格实现 |
| 生图 | 只在概念难以文字说明时生成；生成后裁成元素参考 | 每个模块都重复生整张大图 | 一张母图 → 多个局部参考 |
| 参考图片 | 每个 TASK 只读1–4张局部图 | 每次读取整张视觉展板/整本PDF | REF_01 / REF_02…按任务取用 |
| 稿件处理 | ChatGPT/人工先结构化 Word Styles；Codex只映射 | 让 Codex判断问答、标题、章节语义 | Word Style → InDesign Style |
| 图片素材 | 人工先筛 A/B/C 与 ready/pending；Codex不挑图 | 给 Codex上百张照片让其选择 | assets.csv + ready-only |
| 史实 | 不确定写 pending/null，不让 Codex补全 | 让 Codex“根据上下文推断” | 人工确认后再进入 manifest |
| Prompt | 用固定模板，只传本轮差异 | 每轮重复完整项目背景 | AGENTS + TASK + 1段短提示词 |
| 回复 | 要求 Astra只回 commit / 文件 / TODO / 测试入口 | 让它解释全部代码 | <= 8行 |
| Git | 一任务一 commit；只审当前 diff | 反复读取整个历史 | compare/fetch commit |
| 版本回滚 | 模块冻结后打 tag | 出问题后让模型回忆旧实现 | Git tag 直接回退 |
| 页数 | 不锁最终页码；按内容自然扩展 | 为达到固定页数反复重排 | 4P/8P模块化扩展 |
| 最终组装 | build_magazine.jsx只调用冻结模块 | 重新生成全部模块 | 薄 assembly |
| ChatGPT上下文 | 重要决定写入项目备忘录；接近上下文上限时更新 | 依赖聊天历史记忆所有细节 | MEMORY.md + GitHub双保险 |

## 默认省额度优先级

1. **先减少读取量**：不读就不花推理。
2. **再减少决策量**：我先把设计和参数定好，Codex不思考审美。
3. **再减少生成量**：只写当前模块、只给 diff。
4. **再减少返工量**：先测试结构，再做视觉；冻结后不重写。
5. **最后才考虑压缩回复字数**：回复短只是最小收益，真正的大头是读取、推理和返工。

## 项目固定口令

以后默认遵守：
- 能不让 Codex 读的，就不让它读。
- 能由 ChatGPT/人工提前决定的，就不让 Codex 再决定。
- 能复用的，就不重新生成。
- 能局部修的，就不重构。
- 能用数据文件表达的，就不用自然语言长解释。
- 能用一张裁切参考图表达的，就不让它看整张展板。
- 能用 Git diff 验证的，就不让它重新解释源码。
- 未经实机验证，不冻结；一旦冻结，不为视觉调整改结构代码。

## 3. 用户指定版式（必须肉眼可见）

在《山》现有 185×260mm 裁切尺寸、暖白背景、双栏正文和章节视觉系统中，重排「寄语」：

**每位寄语人的信息头必须横向排列**：

`[有明确背景填充的彩色姓名框]   2020年副会长`
`正文第一段从信息头下方自然开始，后续正文连续流动……`

- **姓名**：可用 muted mineral blue / steel blue / 深酒红等现有刊物协调色，必须是可见的**实色背景填充（shape fill / paragraph shading）**，而不只是描边、文字变色、彩色阴影或左侧竖线。姓名本身需在色块上有足够对比，优先白字；矩形不应做成卡片，留约 1.5—2.5mm 内边距，适配不同姓名长度（如“刘慧颖（昼温）”）。不要求所有姓名框固定相同宽度。
- **职务**：严格放在**姓名框的右边、同一横行**，文字写为原稿原样（如“2014年洪家楼负责人”），用较小无衬线、深灰蓝或炭黑字，基线视觉对齐，不能放到姓名下一行。若个别超长职务同一栏容纳不下，可以为该条适当改变姓名框宽度或微调该头部尺寸；不可隐藏、缩为极小字、擅自删字。
- **正文**：紧接该信息头下面，有独立样式和适度段前间距；不要任何侧边竖线，不要卡片墙，不要给全文加实色底。
- 允许姓名框色系有少量变化，但需全章协调、克制，不能人人随机色。优先设计一个统一母版/样式配置，由数据驱动。
- 正文字号、行距与全刊阅读系统相衔接，不得通过极小字号暴力压缩页数。

## 4. 最重要：自然的跨栏与跨页、填补无效留白

**取消“每位寄语必须作为不可分割单元占据一栏/一页”的限制**。
- 允许**同一位寄语的正文在同一页左右栏连续流动，或从本页延续到下一页**；超过栏剩余高度应直接在下一栏/下一页续接，不能为了“完整放置一个寄语块”留下大片空白。
- 但**姓名+职务信息头必须同处一行**，并与至少正文的前 2—3 行保持在一起。不要出现孤立姓名或只剩一行的孤段。正文适当 keep-together / widow-orphan 控制，不能把**整个**长寄语设置为 `keepTogether=true`。
- 下一位寄语在上一位内容结束后自然接续，不强制新栏/新页；正常使用清楚的组间距。
- 原有双栏阅读顺序必须明确：先左栏从上到下，再右栏，从前页到后页；不得为了填空而打乱28位作者先后次序。
- 对超长稿如姜福铭，允许一人跨 2 页；在接续页不重复大姓名框，必要时可使用小号“续”字样，但不允许将提示语混入稿件正文源。
- 新稿不得再出现失败版第6/7页那样显著的无意义半页以上空白；允许章节尾页合理留白，**不能为了凑满而硬塞装饰**。应通过真实正文文本流、自适应分栏、段落约束求解。
- 不预设严格页数上限。希望在不缩小正文的情况下，使布局比现有7页更有效率；如果最终仍需7页，但使用率明显提高、节奏更合理，也可接受。不可仅以“页数减少”宣称成功。

## 5. 工程实现路径

1. 基于真实 DOCX 标题、职务、正文解析出结构化 28 entries，建立可审计映射：entry_index、source_heading、name、role、body paragraph list、styling exceptions。禁止用从 Review PDF 提取的文本覆盖稿源。
2. 将姓名+职务组成不可拆的**横向头部**（可采用 anchored object group/inline group/tab stop 样式组合），确保名字背景矩形确实渲染。正文使用真正的 threaded story/linked text frames，实现跨栏与跨页，而不是按每人高度堆叠独立固定文本框。
3. 为正文正常流动和信息头 keep-with-next 提供确定的脚本和测试逻辑，杜绝所有人全文 `keepTogether`。
4. 复杂特殊稿（王丰诗歌，兰欣然谜题，姜福铭长文，吴桐思柳标题等）可使用专用 paragraph styles，但仅作版式保真，不改变文字。
5. 模块独立运行，通过后再挂接 Assembly「陆｜山外」；更新目录自动页码与后续奇偶页计算，不硬编码页数。
